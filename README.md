# File Network

PC 파일을 **키워드로 검색**하고, **선택한 폴더를 관심사별 AI 지식 그래프로 탐색**하는 로컬 데스크톱 앱입니다.

## 1. 핵심 기능

1. **키워드 검색 → 파일 목록 → 본문 미리보기·원본 열기.** 파일명·저장 본문의 통합 검색을 기본 제공하며, 필요하면 파일명/본문만 선택할 수 있습니다.
2. **선택 영역 → 자동 준비·전송 승인 → AI 지식 그래프 → 관련 파일 목록.** 관심사 노드를 누르면 해당 파일을, 연결을 누르면 두 관심사에 함께 분류된 파일을 보여줍니다.

파일·본문 구간을 수동으로 골라 질문하는 흐름은 주 화면에서 제공하지 않습니다. 파일 추출·인용 검증·DB는 위 두 기능을 위한 내부 기반입니다.

## 2. 사용 방법

### Windows 배포본

[Windows Desktop Build](https://github.com/wjddydghks/file-network/actions/workflows/desktop.yml)의 성공한 수동 실행에서 **FileNetwork-Windows-x64** artifact를 다운로드합니다. GitHub 로그인이 필요할 수 있고 보관 기간은 14일입니다. ZIP 전체를 풀어 `FileNetwork.exe`를 실행하세요. `_internal` 폴더를 유지해야 하며 Python 설치는 필요 없습니다.

이전 실행의 ZIP은 이후 main 변경을 자동 반영하지 않습니다. Windows x64 개발용 미서명 배포본이며 코드 서명·설치 마법사·자동 업데이트는 아직 없습니다. 배포본 DB는 `%LOCALAPPDATA%\file-network\file_network.db`에 저장합니다. 소스 실행의 DB와 별도이므로 처음에는 분석이 필요할 수 있습니다.

### 소스 실행

Python 3.12를 CI 기준으로 사용합니다. Windows CMD 예:

```bat
git clone https://github.com/wjddydghks/file-network.git
cd file-network
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements-gui.txt
python -m app.gui
```

Linux/macOS는 `source .venv/bin/activate`로 활성화합니다. Linux Qt 실행에는 `libegl1 libopengl0 libxcb-cursor0 libxkbcommon-x11-0 libxcb-icccm4 libxcb-keysyms1` 등의 시스템 라이브러리가 필요할 수 있습니다. 소스 DB는 `database/file_network.db`이며 원본 파일을 임의로 수정하거나 삭제하지 않습니다.

### 파일 검색

- 왼쪽에서 폴더를 선택하고 **폴더 분석**을 실행합니다. 하위 디렉터리도 분석합니다.
- 키워드를 입력해 검색합니다. 여러 단어는 파일명 또는 본문에 모두 포함되어야 하며, 이름과 본문에 단어가 나뉘어 있는 것만으로 일치하지 않습니다. 본문 일치를 먼저 보여주고 중복 파일을 제거합니다.
- 파일을 선택해 미리보기·원본 열기를 사용합니다. 검색 결과에서 원본을 자동으로 실행하지 않습니다.
- **모든 분석 폴더**는 저장된 전체 검색 범위입니다. 선택 폴더의 저장 파일·본문 검색 가능·미분석/실패 상태와 최근 스캔/본문 저장 시각을 표시합니다.
- 상위 폴더 분석으로 포함된 하위 범위도 저장된 파일만 집계합니다. 스캔 완료를 본문 분석 완료로 표시하지 않으며 원본의 변경은 다시 분석해야 확인됩니다.
- **분석 설정**에서 파일 크기(기본 10MiB), 텍스트 인코딩, 제외 폴더명을 설정합니다. 제외 폴더명은 모든 깊이에 적용하고 제외된 기존 DB 자료를 자동 삭제하지 않습니다.

### AI 지식 그래프

1. 폴더를 선택하고 왼쪽 **AI 지식 그래프**를 엽니다. 검색의 전체 폴더 옵션과 별개로 현재 선택한 폴더 하나를 분석합니다.
2. 파일을 로컬에서 확인·분석하고, 파일마다 처음/가운데/끝의 **최대 900자 대표 본문**을 자동 준비합니다. 본문 구간을 직접 고를 필요가 없습니다. 로컬 준비까지 API 키나 외부 호출은 필요 없습니다.
3. 이전 결과가 같은 파일 상태·관심사·모델과 일치하면 즉시 재사용합니다. 키 없이도 저장 그래프를 탐색할 수 있습니다.
4. 새 분석은 **분석·전송 확인**에서 파일별 실제 준비 본문, 차단/본문 없음/재사용 여부, 예정 호출 수와 고정 분석 지시를 확인합니다. 목록은 80개씩 전부 확인할 수 있습니다.
5. 관심사는 선택 사항입니다. 예: `일정, 비용, 보안`. 비우면 자동 구성합니다. 설정을 바꾸면 **영역 분석 준비**를 다시 누르세요.
6. 본인 OpenAI 키를 입력하고 외부 AI 허용·전송 확인·호출 상한에 동의하면 일괄 분류를 시작합니다. 키는 현재 창 메모리에서만 쓰고 환경변수 `OPENAI_API_KEY`로도 지정할 수 있습니다. 키를 저장소·채팅·공유 화면에 올리지 마세요. ChatGPT 구독과 API 결제는 별개입니다.
7. **큰 관심사 클릭 → 세부 주제 펼치기 → 관련 파일 목록**, **실선 클릭 → 세부 주제 파일**, **점선 클릭 → 공통 파일 목록**, **파일 선택 → 분류 이유·근거·본문 미리보기·원본 열기**로 탐색합니다. 작은 노드와 연결은 선택 목록으로도 고를 수 있습니다.

관심사 노드는 대표 본문을 근거로 한 **AI 분류**입니다. 큰 관심사와 세부 주제는 실선으로 연결합니다. 파일이 두 주제에 분류되면 점선으로 연결하며, 이는 공통 파일이 있다는 의미입니다. 인과관계·문서 선후 관계·실제 업무 관계를 확정하지 않습니다. 파일별 이유와 실제 준비 본문에 있는 근거를 확인하세요. 대표 본문은 문서 전체가 아니므로 분류 품질을 보장하지 않습니다.

미분석·재분석 필요·실패·건너뜀·설정 제외·전송 차단·AI 미분류·분류 대기 파일도 처리 현황과 선택 목록에 남깁니다. 처리 상태를 관심사 노드로 표시하지 않습니다. 첫 페이지만 분석한 것으로 처리하지 않고 선택 영역의 저장 파일 전체를 준비합니다. 영역당 최대 **10,000개**를 지원하며 초과하면 더 작은 하위 폴더를 선택해야 합니다. 검색 대상은 DB에 저장된 파일이며 접근 오류·제외 설정으로 누락된 원본 파일이 없는 것처럼 단정하지 않습니다.

### 자동 분류·비용·재개

- **모든 전송 가능 파일을 16개씩 요약**한 후 전체 요약에서 분류 기준을 만듭니다. 일부 대표 파일로 기준을 고정하지 않습니다. 요약이 많으면 최대 64개씩 주제를 통합하고, 전체 결과가 하나의 요청에 들어올 때까지 단계적으로 합칩니다. 각 단계에서 입력 요약이 빠짐없이 정확히 한 그룹에 포함되는지 검증합니다. 소수 주제도 설명에 보존하도록 지시하지만 의미 보존 자체를 보장하지는 않습니다.
- 전체 요약을 바탕으로 **큰 관심사 최대 8개 → 세부 주제 최대 48개 → 파일** 구조를 구성합니다. 기타·일반 자료·문서 형식처럼 모호한 이름은 거부합니다. 모든 파일을 16개씩 세부 주제에 분류하며 각 파일은 0~2개 세부 주제에 속합니다. 큰 관심사에는 하위 주제의 파일을 중복 없이 합쳐 표시합니다.
- 이름·경로·실제 파일 ID는 보내지 않고 별칭과 자동 준비 본문·관심사, 생성된 요약·핵심어·주제·근거를 전송합니다. 파일별 본문은 요약과 최종 분류에 각각 전송될 수 있습니다. 요약·통합 주제·관심사 이름과 설명은 후속 요청에 재사용하며 민감정보 가능성이 있으면 차단합니다.
- 요약과 파일 분류의 근거는 앱이 준비한 원문 구절 번호에서 AI가 선택합니다. 근거 문장을 AI가 다시 작성하지 않고, 앱이 번호에 해당하는 정확한 원문을 저장합니다. 다른 파일의 번호·없는 번호는 거부하며 기존에 검증한 완료 배치는 이어서 사용할 수 있습니다.
- 파일별 분류 누락·중복·없는 파일·없는 관심사·실제 전송 및 저장 본문에 없는 근거를 거부합니다. 분류 근거는 최대 160자이며 발췌 경계에 걸친 가공 문장을 원문으로 인정하지 않습니다. **근거 존재 검증은 AI 해석의 사실성을 보장하지 않습니다.**
- 관심사를 구성하지 못하면 나머지 파일을 분류했다고 표시하지 않습니다. 관심사를 구체화해 새 승인 후 다시 준비할 수 있습니다.
- 기본 모델은 `gpt-4.1-mini`이며 구조화 응답 지원 모델을 지정할 수 있습니다. 최대 출력은 상·하위 관심사 구성 12,000토큰/요약·주제 통합·파일 배치 10,000토큰, 응답은 각각 64KiB입니다. 파일 수에 따른 최대 예정 호출 수를 보여주며 실제 금액 견적이나 계정 전체 금액 한도는 아닙니다.
- 호출 상한은 한 번 승인한 작업에 적용됩니다. 상한에 도달하면 완료 배치를 저장하고 멈춥니다. **영역 분석 준비**를 다시 하면 같은 영역 상태에서 미완료 요약·주제 통합·분류만 승인해 재개합니다. 자동 재시도는 없습니다.
- 중단·닫기·시간 초과도 이미 전송/과금되었을 수 있습니다. 진행 중인 요청이 끝난 뒤 창을 닫으며, 검증해 저장한 배치는 유지합니다. 같은 영역·관심사·모델의 동시 실행을 잠그고 강제 종료 시 잠금은 최대 3분 뒤 복구할 수 있습니다.
- 파일 요약·핵심어, 주제 통합 결과, 상·하위 관심사, 분류 결과와 근거는 로컬 DB의 `knowledge_graphs`에 저장합니다. 원본 파일을 수정하거나 AI가 DB에 직접 접근하지 않습니다. 키와 전송 원문 전체는 결과/로그에 저장하지 않습니다. 분류 근거의 일부 문장은 결과에 보관합니다.
- 이전 단일 계층 분류 결과는 새 방식의 완료 결과로 재사용하지 않습니다. 전체 요약부터 새 승인 후 다시 생성합니다.
- 파일·경로·제외 설정·관심사·모델이 바뀌면 이전 전체 분류는 최신으로 사용하지 않습니다. **영역 분석 준비**가 다시 로컬 파일을 확인하고 새 전송 계획을 만듭니다. 파일 변경 이후에는 전체 새 분류가 필요할 수 있으며 완료 배치 재사용은 같은 영역 상태의 중단/재개에 해당합니다.

## 3. AI 활용 및 보안 정책

### 3.1 AI 활용 범위

선택 영역의 파일을 관심사별로 분류하고, 관련 파일을 지식 그래프로 탐색하는 데 사용합니다. 외부 API 사용은 선택 사항이며 로컬 검색은 독립 실행합니다.

### 3.2 로컬 우선 처리 원칙

- 파일 원본은 사용자의 로컬 파일 시스템에 유지합니다.
- 파일 메타데이터와 검색 데이터베이스는 로컬에서 관리합니다.
- 파일 스캔, DB 조회, 검색 대상 선정은 로컬 엔진에서 수행합니다.
- 외부 AI API는 사용자가 AI 분석을 요청한 경우에만 사용합니다.
- AI가 DB에 직접 접속하거나 파일을 임의로 수정하지 못하도록 역할을 분리합니다.

### 3.3 외부 API 데이터 전송 정책

외부 생성형 AI API를 사용할 때는 다음 정책을 적용하는 것을 목표로 합니다.

1. **최소 데이터 전송:** 분석에 필요한 문서 일부와 문맥만 선별해 전송합니다. 원본 파일 전체를 기본적으로 전송하지 않습니다.
2. **사용자 승인:** 외부 전송 전에 대상 파일과 전송할 내용을 확인하고 승인할 수 있도록 합니다.
3. **민감정보 보호:** 개인정보, 인증정보, 기밀정보 등이 포함된 데이터는 탐지 후 기본적으로 전송을 차단하거나 로컬 분석만 허용합니다.
4. **비식별화:** 분석에 불필요한 이름, 연락처, 식별 정보 등은 가능한 범위에서 마스킹하거나 대체합니다. 단, 마스킹만으로 재식별 위험이 완전히 사라지는 것은 아닙니다.
5. **전송 범위 통제:** 사용자가 선택한 파일과 검색 결과 중 필요한 데이터만 전송합니다.
6. **API 키 보호:** API 키를 소스 코드나 저장소에 포함하지 않고 환경변수 또는 안전한 비밀정보 관리 방식을 사용합니다.
7. **전송 기록 관리:** 전송 여부와 대상 등 필요한 기록을 남기되, 민감한 원문이 로그에 불필요하게 저장되지 않도록 합니다.
8. **제공 업체 정책 확인:** API 제공 업체의 데이터 보관, 학습 사용 여부, 삭제 및 처리 정책을 확인한 뒤 사용합니다.

### 3.4 로컬 전용 모드

외부 API 사용을 원하지 않는 사용자를 위해 외부 전송을 비활성화할 수 있는 로컬 전용 모드를 지향합니다.

- 로컬 파일 스캔 및 DB 관리는 계속 사용할 수 있어야 합니다.
- 로컬에서 가능한 검색과 분석 기능은 외부 API 없이 동작하도록 설계합니다.
- 외부 AI 분석 기능은 비활성화하거나 사용할 수 없음을 명확히 표시합니다.

> **중요:** 외부 API로 데이터를 전송하는 순간 전송된 데이터에 대한 제3자 처리 위험이 발생할 수 있습니다. 일부 데이터만 보내거나 마스킹하더라도 보안이 완전히 보장되는 것은 아닙니다. 민감하거나 기밀인 문서는 외부 전송을 차단하는 것을 기본 원칙으로 합니다.

## 4. 파일 처리와 검색 범위

텍스트·소스 코드·PDF·DOCX·XLSX·PPTX의 내용을 로컬에서 추출합니다. 이미지 PDF OCR과 구형 DOC/XLS/PPT는 지원하지 않습니다. UTF-8/BOM UTF-16·UTF-32 및 명시적 CP949를 지원합니다. PDF/Office의 복잡한 요소·암호·페이지/슬라이드/압축 해제 제한 때문에 실패·건너뜀이 있을 수 있으며 파일별 상태에서 확인합니다.

증분 분석은 새 파일·수정·이동·삭제를 반영하고 유효한 추출 캐시를 재사용합니다. 분석을 취소해도 이미 커밋한 결과는 남으며 미완료 스캔에서 보지 못한 파일을 삭제로 처리하지 않습니다. DB와 보조 파일은 앱이 자기 자신을 분석하지 않도록 제외합니다. 폴더 심볼릭 링크를 따라 전체 영역을 확장하지 않습니다.

본문 검색은 로컬 SQLite FTS5 키워드 검색이며 의미 검색·OCR 검색은 아닙니다. 파일명은 NFC·대소문자 접기 후 부분 문자열로 검색합니다. 검색어는 최대 4,096자/100단어이며 잘못된 입력으로 기존 결과를 지우지 않습니다. 결과 수는 1~1000 범위입니다.

## 5. 검증 및 배포

```bash
python -m pytest -q
python -m compileall -q app core database services tests benchmarks scripts desktop.py
```

일반 CI는 Windows/macOS/Linux 테스트와 Windows 혼합 문서 600개 검증을 실행합니다. **EXE·ZIP은 매번 만들지 않습니다.** Windows 배포 workflow를 수동 실행하면 같은 코드의 세 OS 테스트 후 PyInstaller 빌드 및 Python 환경을 분리한 실제 EXE 실행 검증을 진행합니다.

자동 테스트는 모의 API 응답으로 승인·전송 차단·분류·근거·저장·재개·그래프 탐색을 확인합니다. 개발/CI에서 실제 문서를 외부로 보내거나 유료 API를 호출하지 않습니다. **실제 계정의 인증·모델 접근·결제·분류 품질은 본인 키와 허용한 문서로 별도 검증해야 합니다.**

## 9. Git 협업 규칙

프로젝트 변경 사항은 Issue를 기반으로 관리하며, 기능 개발과 수정은 별도 브랜치에서 진행합니다.

### 9.1 Issue

제목 형식:

```text
[Type] 작업 내용
```

| Type | 설명 |
|---|---|
| Feature | 신규 기능 |
| Bug | 버그 수정 |
| Refactor | 코드 구조 개선 |
| Test | 테스트 작성 및 개선 |
| CI | CI/CD 및 자동화 |
| Docs | 문서 수정 |
| Chore | 기타 설정 및 유지보수 |

Issue에는 작업 배경, 목표, 세부 작업, 완료 조건을 포함합니다.

### 9.2 Branch

브랜치 이름 형식:

```text
type/issue-number-description
```

예시:

```text
feature/12-content-analyzer
fix/15-symlink-scan
test/18-scanner-test
docs/20-readme-update
```

- `main` 브랜치에 직접 작업하지 않습니다.
- Issue에 연결된 별도 브랜치에서 작업합니다.

### 9.3 Commit

커밋 메시지 형식:

```text
type: 작업 내용
```

예시:

```text
feat: add document content extraction
fix: handle inaccessible directories
refactor: separate scanner logic
test: add incremental scan tests
docs: update readme
```

### 9.4 Pull Request

모든 변경 사항은 Pull Request를 통해 `main`에 반영합니다.

PR에는 관련 Issue, 주요 변경 사항, 테스트 결과 및 확인 사항을 포함합니다. 관련 Issue는 `Closes #이슈번호`로 연결합니다.
